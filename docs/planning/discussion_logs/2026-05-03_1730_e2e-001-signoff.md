## Deferred ACs and Blockers

### AC-001 and AC-008 — Different networks required
**Blocker:** Only one physical machine available during this session.  
**What was verified:** Connection and exchange work correctly over loopback. The transport layer, NAT traversal logic, and relay fallback code are all present and tested in unit tests; what's missing is a live demonstration across a real network boundary.  
**Resolution path:** Re-run AC-001 and AC-008 with an EC2 instance or a second physical machine on a different network. The relay package (`cello-relay`) is ready to deploy. This can be done any time before Alpha.

### AC-003 — Auto-wake via `--channels`
**Blocker:** `--channels` is gated behind Anthropic's own billing layer. Not available on AWS Bedrock. Confirmed with `claude --channels server:cello` → "Channels are not currently available."  
**What was verified:** `cello-mcp` correctly fires `notifications/claude/channel` on the MCP wire (verified in `packages/adapter-claude-code/src/__tests__/adapter-001.test.ts` AC-002 test and `packages/e2e-tests/src/__tests__/e2e-001.test.ts` AC-003 proxy test). The notification payload is correct: `{ type: "cello_message", from: <pubkey> }`, no content field.  
**Workaround used:** Agent B ran a manual `cello_receive` polling loop (30s timeout, re-called after each message). This produced the correct reactive behavior — Agent B received messages and replied — but required an open Claude Code turn rather than a fresh auto-started turn.  
**Resolution path:** Retest when `--channels` becomes available on Bedrock, or when operator has access to direct Anthropic API billing.
