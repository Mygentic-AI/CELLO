# MSG-004 Phase P — Pseudocode (rev 2)

Story: dual-path send/receive across `/cello/content/1.0.0` (peer↔peer) and `/cello/relay/1.0.0`
(client↔relay), cross-check on receipt, per-session outbound serialization queue, desync
fail-closed after any validation failure.

Crypto references:
- SHA-256 leaf prefix: `SHA-256(0x00 || content)` per MERKLE-001
- Structure 1 TBS: `[1, content_hash, sender_pubkey, session_id, last_seen_seq, timestamp]` per MERKLE-002
- Ed25519 signing and verification per RFC 8032
- Canonical CBOR encoding per RFC 8949 §4.2.1
- Merkle tree construction and root per MERKLE-001 (RFC 6962)

## Review findings addressed

Rev 2: C-1, H-1, H-2, H-3, M-1, M-2, M-3

Rev 3: echo resolver fired from `crossCheckDelivery`; `last_seen_seq` update moved into same fn.

Rev 4 (this version):
- **Issue 3 (rev3 review)**: `sendMessageLocked` now re-checks `session.desynchronized` after
  `waitForOwnEcho` returns — prevents a desync-triggered resolver fire from producing `{ok:true}`.
- **Issue 4 (rev3 review)**: `desync()` now iterates `pending_s2` entries and fires any stored
  `echo_resolve` before clearing the map — prevents permanent hang when the resolver migrated
  from `own_echo_resolvers` into a `PendingS2Entry` before desync fired.

## Wire format change: `leaf_deliver` must carry `structure1_cbor` (H-3)

The receiver needs `last_seen_seq` and `timestamp` from Structure 1 to:
1. Call `verifyStructure2Signature(s2, session_id, last_seen_seq, timestamp)` (Ed25519 verify)
2. Run the causal chain check: `s1.last_seen_seq <= session.last_seen_seq`

These fields are not present in the decoded `Structure2` object. They are in the Structure 1 TBS
that the sender signed. The relay already stores `structure1_cbor` in its leaf log (relay-node.ts
line 400). It must also include it in the `leaf_deliver` frame.

**Change to relay-types.ts `LeafDeliver`:**
```typescript
interface LeafDeliver {
  type: "leaf_deliver";
  session_id: Uint8Array;       // 16 bytes (unchanged)
  leaf_kind: number;             // 0x00 or 0x02 (unchanged)
  structure2_cbor: Uint8Array;  // (unchanged)
  structure1_cbor: Uint8Array;  // NEW — the exact bytes the sender signed
}
```

**Change to relay-frames.ts `encodeLeafDeliver`:** include `structure1_cbor` in the CBOR map.
**Change to relay-frames.ts `decodeInboundFrame`:** N/A — `leaf_deliver` is outbound from relay.
The relay's `#processHashSubmitLocked` already has `frame.structure1_cbor` at hand; include it
in the `encodeLeafDeliver` call.

## Key data model additions to `SessionRecord` (client/types.ts)

```
SessionRecord additions:
  +  local_tree_leaves: Array<{ kind: "msg"|"ctrl"; s2_cbor: Uint8Array }>
       // grows on each accepted leaf; used to recompute prev_root locally
  +  next_expected_seq: number         // starts at 1; incremented on each accepted leaf
  +  last_seen_seq: number             // (already exists) = highest seq of OUR OWN sends,
                                        // as confirmed by the relay's echoed leaf_deliver.
                                        // Used as `last_seen_seq` field in Structure 1 TBS.
                                        // Updated ONLY after our own echoed leaf_deliver arrives.
  +  desynchronized: boolean           // fail-closed flag; starts false

  // Pending cross-check buffers:
  +  pending_s2: Map<contentHashHex, PendingS2Entry>  // Structure 2 arrived, awaiting content_frame
  +  pending_content: Map<contentHashHex, PendingContentEntry>  // content arrived before S2
       // pending_content is bounded at 256 entries; LRU eviction on overflow (M-1)

  interface PendingS2Entry {
    s2: Structure2              // decoded
    s2_cbor: Uint8Array         // for leaf append
    s1_fields: Structure1Fields // decoded from structure1_cbor (last_seen_seq, timestamp, etc.)
    leaf_kind: number           // 0x00 or 0x02 — needed in crossCheckDelivery
    session_id: Uint8Array
    sequence_number: number
    content_hash: Uint8Array
    is_own_send: boolean        // true if s2.sender_pubkey == myPubkey
    arrived_at: number          // wall clock ms, for 30s grace timer
    timer_handle: ReturnType<typeof setTimeout>
    // echo_resolve is set iff is_own_send == true; fires after crossCheckDelivery completes
    echo_resolve?: () => void
  }

  interface PendingContentEntry {
    content_bytes: Uint8Array
    arrived_at: number
    // No timer started (AC-010: no desync on orphaned content alone)
  }

  // Outbound: per-session serialization
  +  outbound_lock: Promise<void>      // promise chain; resolved when last send fully echoed
  +  own_echo_resolvers: Map<seqNum, () => void>  // seq_num -> resolve fn from waiting send
```

**Note on `last_seen_seq` field**: `session.last_seen_seq` (already in SessionRecord from
SESSION-002) is reused. It starts at 0. It is updated to `echoed_s2.sequence_number` after
the relay delivers back our own message's Structure 2. It is the value embedded in Structure 1
TBS as the sender's `last_seen_seq` claim.

`genesis_prev_root` is already in `SessionRecord` (from SESSION-002 AC-002) — populated by
`computeGenesisPrevRoot(pubA, pubB, session_id, session_timestamp)` during
`receiveSessionAssignment`. No change needed (M-2 addressed by confirming it is already there).

## Relay stream: persistent per session

A persistent relay stream is opened during `receiveSessionAssignment` (step 5, already present).
MSG-004 starts a background reader loop on that stream to consume `leaf_deliver` frames
and `hash_submit_ack` frames:

```
startRelayStreamReader(sessionIdHex, relayStream):
  for await chunk in lp.decode(relayStream):
    frame = decode(chunk)
    if frame.type == "hash_submit_ack":
      handleHashSubmitAck(sessionIdHex, frame)
    elif frame.type == "leaf_deliver":
      handleInboundLeafDeliver(sessionIdHex, frame)
    elif frame.type == "hash_submit_error":
      // surface to the waiting sendMessage caller via a per-request resolver
      handleHashSubmitError(sessionIdHex, frame)
  // stream ended → relay disconnected (DB-001)
  markRelayDisconnected(sessionIdHex)
```

The reader runs in the background as a fire-and-forget async task started from
`receiveSessionAssignment`.

## sendMessage(sessionIdHex, content): Promise<SendMessageResult>

```
// Outbound serialization: one send fully echoed before next is signed.
// The lock releases only after our own echoed leaf_deliver arrives (C-1 fix).
// Per RFC 8949 §4.2.1 (CBOR), RFC 8032 (Ed25519), FIPS 180-4 (SHA-256)

async sendMessage(sessionIdHex, content):

  // Acquire per-session outbound lock (promise chain serialization)
  return await acquireOutboundLock(sessionIdHex, () => sendMessageLocked(sessionIdHex, content))

async sendMessageLocked(sessionIdHex, content):

  1. Look up session record → session_not_found if absent
  2. if session.desynchronized → return { ok:false, reason:"session_desynchronized" }
  3. if session.relay_stream is closed/null → return { ok:false, reason:"transport_unavailable" }

  4. content_hash = SHA-256(0x00 || content)   // MERKLE-001 leaf prefix, FIPS 180-4

  5. Build Structure 1 TBS:
       tbs = canonical_cbor([1, content_hash, myPubkey, session_id,
                              session.last_seen_seq, now_ms])
       // per MERKLE-002, RFC 8949 §4.2.1
  6. signature = await keyProvider.sign(tbs)    // Ed25519 per RFC 8032

  7. Submit to relay via hash_submit on persistent relay stream:
       { type:"hash_submit", session_id, leaf_kind:0x00,
         structure1_cbor: tbs,
         sender_signature: signature }
     → wait for hash_submit_ack { sequence_number: mySeq } OR hash_submit_error
     → if error → return { ok:false, reason: map error reason }
     (Note: ack arrives on the relay stream reader loop and is routed to this caller
      via a per-request Promise resolver stored in session.pending_ack_resolve)

  8. Send content bytes to counterparty on /cello/content/1.0.0:
       open new stream to counterparty (dial from cached multiaddrs if not connected)
       write LP-framed { type:"content_frame", session_id, content_hash, content_bytes: content }
       half-close write side (no ACK expected in M1)
       // Content path failure does not abort the hash path; the receiver's 30s grace
       // timer will fire and desync the session via content_missing — designed fail-closed.

  9. Wait for our own echoed leaf_deliver (sequence_number == mySeq):
       // Create a Promise and store its resolve fn in session.own_echo_resolvers[mySeq].
       // crossCheckDelivery fires the resolver AFTER appending the leaf and updating last_seen_seq.
       // desync() also fires all resolvers (including ones migrated to PendingS2Entry) to unblock.
       await waitForOwnEcho(sessionIdHex, mySeq)
       // Re-check desynchronized: desync() resolves the waiter without an error, so we must
       // check here to avoid returning ok:true on a desync-interrupted send (Issue 3 fix).
       if session.desynchronized → return { ok:false, reason:"session_desynchronized" }

  10. return { ok:true }
  // Lock releases via the promise chain on return
```

**DB-001 (relay disconnect):** when the relay stream closes (detected in stream reader loop),
`session.relay_stream = null`. Any `sendMessage` call that reaches step 3 returns
`transport_unavailable` immediately with no state mutation.

  resolver = session.pending_ack_resolve

    resolver({ ok:true, sequence_number: ack.sequence_number })
    session.pending_ack_resolve = null

## handleInboundLeafDeliver(sessionIdHex, frame: LeafDeliver): void

Called from relay stream reader for every `leaf_deliver` frame.
`frame` carries: `session_id`, `leaf_kind`, `structure2_cbor`, `structure1_cbor` (H-3 fix).

```
  1. Look up session by sessionIdHex
  2. if session.desynchronized → discard, log
  3. Decode Structure 2 from frame.structure2_cbor
     → if malformed → desync("structure2_malformed"), return

  4. Validate Structure 2 field lengths (sender_pubkey=32, content_hash=32,
     sender_sig=64, prev_root=32, scan_result sentinel shape)
     → if invalid → desync("structure2_fields_invalid"), return

  5. Confirm sequence_number vs next_expected_seq:
     if s2.sequence_number < session.next_expected_seq:
       → desync("sequence_replay"), return    // H-1 fix
     if s2.sequence_number > session.next_expected_seq:
       → desync("sequence_gap"), return       // H-1 fix
     // exact match falls through

  6. Decode Structure 1 from frame.structure1_cbor:
     s1 = decode_structure1(frame.structure1_cbor)
     → if null → desync("structure1_malformed"), return

  7. Verify Ed25519 signature over Structure 1:
     // verifyStructure2Signature reconstructs TBS from s2 fields + s1.last_seen_seq + s1.timestamp
     // and verifies s2.sender_signature against s2.sender_pubkey per RFC 8032
     if !verifyStructure2Signature(s2, session_id, s1.last_seen_seq, s1.timestamp):
       → desync("signature_verification_failed"), return

  8. Confirm prev_root:
     if session.local_tree_leaves.length == 0:
       expected_prev_root = session.genesis_prev_root  // populated in receiveSessionAssignment
     else:
       expected_prev_root = merkleRoot(buildMerkleTree(session.local_tree_leaves))
     if s2.prev_root != expected_prev_root:
       → desync("prev_root_mismatch"), return

  9. Causal chain check:
     // s1.last_seen_seq is the counterparty's claim of what they have seen from OUR side.
     // Our side's canonical ceiling is session.last_seen_seq (last seq the relay echoed for us).
     // A claim above our ceiling means the relay forged or misordered a leaf.
     if s1.last_seen_seq > session.last_seen_seq:
       → desync("sequence_causal_inconsistency"), return

  10. Determine if this is our own send:
      is_own = (s2.sender_pubkey == myPubkey)

  11. Look up matching content in pending_content[content_hash_hex]:
      if found:
        remove from pending_content
        recompute content_hash' = SHA-256(0x00 || buffered_content_bytes)
        if content_hash' != s2.content_hash:
          → desync("content_hash_mismatch"), return
        // Retrieve echo resolver for own sends BEFORE calling crossCheckDelivery
        echo_resolve = is_own ? session.own_echo_resolvers.get(s2.sequence_number) : undefined
        if is_own: session.own_echo_resolvers.delete(s2.sequence_number)
        → crossCheckDelivery(session, s2, frame.structure2_cbor, frame.leaf_kind,
                             buffered_content_bytes, is_own, echo_resolve)
      else:
        // S2 arrived before content — buffer and start grace timer
        echo_resolve = is_own ? session.own_echo_resolvers.get(s2.sequence_number) : undefined
        if is_own: session.own_echo_resolvers.delete(s2.sequence_number)
        buffer PendingS2Entry {
          s2, s2_cbor: frame.structure2_cbor, s1_fields: s1,
          leaf_kind: frame.leaf_kind, session_id, sequence_number: s2.sequence_number,
          content_hash: s2.content_hash, is_own_send: is_own,
          arrived_at: now, echo_resolve,  // resolver stored here; fires from crossCheckDelivery
          timer_handle: setTimeout(30s, () => {
            if session.pending_s2 still contains this entry:
              remove entry; desync("content_missing", {session_id, sequence_number, content_hash})
          })
        } → session.pending_s2[content_hash_hex]
  // Note: last_seen_seq update and echo resolver fire happen inside crossCheckDelivery, not here.
```

## crossCheckDelivery(session, s2, s2_cbor, leaf_kind, content_bytes, is_own_send, echo_resolve?):

```
  1. Append to session.local_tree_leaves: { kind: leaf_kind==0x00?"msg":"ctrl", s2_cbor }
  2. session.next_expected_seq += 1
  3. leaf_hash = SHA-256(leaf_kind_byte || s2_cbor)  // leaf_kind_byte is the 0x00 or 0x02 byte
  4. Enqueue to session MCP receive queue:
       { content: content_bytes, sender_pubkey: s2.sender_pubkey,
         sequence_number: s2.sequence_number, leaf_hash }
  5. if is_own_send:
       session.last_seen_seq = s2.sequence_number  // update after tree append (Issue 2 fix)
       echo_resolve?.()                             // unblock outbound lock (Issue 1 fix)
  // last_seen_seq is NOT updated for counterparty leaves — only for our own echoed sends.
  // The outbound lock (waitForOwnEcho) can now proceed; local tree already includes this leaf.
```

## handleInboundContentFrame(stream from /cello/content/1.0.0):

```
  1. Read LP-framed CBOR → decode ContentFrame { type, session_id, content_hash, content_bytes }
     → if malformed → close stream, ignore
  2. Look up session by session_id hex
  3. if absent or session.desynchronized → close stream, discard
  4. content_hash' = SHA-256(0x00 || content_bytes)
  5. if content_hash' != frame.content_hash:
     // Frame is internally inconsistent — sender computed content_hash wrong or corrupted transit
     // Treat as orphaned: discard silently (no session desync; let the S2 timer fire if one exists)
     log "content_frame_hash_mismatch_internal" (not a desync event; protocol violation by sender)
     close stream
     return
  6. Look up matching s2 in session.pending_s2[content_hash'_hex]:
     if found:
       remove from pending_s2 (cancel its 30s timer via clearTimeout(entry.timer_handle))
       // re-verify hash (belt-and-suspenders; should always match given step 5)
       // Pass is_own_send and echo_resolve from entry so crossCheckDelivery can update last_seen_seq
       // and fire the outbound lock resolver — critical for content-leads-S2 path (Issue 2 fix)
       → crossCheckDelivery(session, entry.s2, entry.s2_cbor, entry.leaf_kind, content_bytes,
                            entry.is_own_send, entry.echo_resolve)
     else:
       if session.pending_content.size >= 256:
         evict oldest entry (LRU/FIFO) silently  // M-1 fix
       session.pending_content[content_hash'_hex] = { content_bytes, arrived_at: now }
       log "content_without_hash" { session_id, content_hash: content_hash'_hex }  // M-3 fix
       // No timer started per AC-010
  7. Close stream
```

## Desync helper:

```
desync(session, reason, extra_fields):
  session.desynchronized = true
  // Cancel pending_s2 timers AND fire any migrated echo resolvers (Issue 4 fix):
  // When a send's resolver was moved from own_echo_resolvers into a PendingS2Entry before
  // desync fired, it would not be reached by iterating own_echo_resolvers. Fire it here
  // so the waiting sendMessage unblocks and hits the session.desynchronized re-check.
  for entry in session.pending_s2.values():
    clearTimeout(entry.timer_handle)
    entry.echo_resolve?.()
  session.pending_s2.clear()
  session.pending_content.clear()
  // Unblock any remaining waiting sends (resolvers still in own_echo_resolvers map):
  for resolve in session.own_echo_resolvers.values():
    resolve()  // sendMessage re-checks session.desynchronized after waitForOwnEcho returns
  session.own_echo_resolvers.clear()
  log { event: reason, session_id, ...extra_fields }
```

## Outbound serialization queue (AC-011, SI-003):

```
// Per-session promise chain. One send fully echoed before next is signed.
// The lock releases only AFTER the echoed leaf_deliver is processed and
// last_seen_seq is updated — not after the ack (C-1 fix).

#outboundQueues = Map<sessionIdHex, Promise<void>>

async acquireOutboundLock(sessionIdHex, fn):
  const prev = #outboundQueues.get(sessionIdHex) ?? Promise.resolve()
  let release!: () => void
  const next = new Promise<void>((r) => { release = r })
  #outboundQueues.set(sessionIdHex, prev.then(() => next))
  await prev
  try:
    return await fn()
  finally:
    release()

// Cleanup: on session close or desync, delete the queue entry so the chain
// does not accumulate across the session lifetime (L-1 note).
```

## Tradeoffs noted:

1. **Echo-gated outbound lock (C-1)**: adds one relay RTT latency per send (ack arrives ~same time
   as echo in practice). Spec explicitly accepts this: "bounds throughput per session to one
   client↔relay RTT per message."

2. **pending_content 256-entry LRU bound (M-1)**: not in the ACs, but unbounded accumulation
   from a buggy/malicious peer is a real concern for long sessions. 256 is consistent with the
   relay and directory notification queue bounds already in the codebase.

3. **Our own leaf_deliver cross-checked (both paths)**: the sender's own content stream send
   is not short-circuited even though we know the content. This keeps the cross-check symmetric
   and avoids a code path that only runs for counterparty messages, which would reduce test coverage
   and could mask a bug where the relay modified the content_hash.
