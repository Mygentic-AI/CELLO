## Key ideas surfaced

**"Lost the lookup service, not the history"**
The cleanest statement of the graceful-degradation design goal. A directory outage drops you to K_local-only mode — you can verify endorsements you already hold, you just can't discover new peers. The history is client-side and survives any server failure.

**"Honest about what can't be solved, aggressive about what can be bounded"**
Proposed here as the CELLO design philosophy. The bootstrap problem has no clean solution; every distributed trust system just argues about how bad day-zero compromise is. CELLO's answer is to minimize blast radius: FROST breaks silent minting, client-side storage means directory breach destroys availability not history, and the attack surface shrinks from "any CA in a 100-CA bundle" to "the install artifact."

**Agent-as-notary: operator-as-chain-of-custody**
Ephemeral key + verifiable transcript = provenance without attribution. The missing link is an operator signing a statement: "pubkey X was my Claude instance at time T." This is the same logic as a notary — the notary doesn't remember your signing, but their seal creates the chain. The transcript becomes citable not because the key is trusted in isolation but because the chain of custody is documented. This is the blueprint for CELLO's citation infrastructure for agent conversations.

**The blast-radius framing**
The right way to characterize CELLO's security model is not "we escaped the CA problem" — we didn't. It's that we minimized the damage a compromised anchor can do. A rogue CELLO directory can censor (lie about availability) but cannot forge (FROST blocks this). Endorsement history survives on client devices. Compare to the browser CA model: one rogue CA, every HTTPS session is suspect. CELLO's failure mode is strictly better even if it doesn't eliminate the trust anchor.
