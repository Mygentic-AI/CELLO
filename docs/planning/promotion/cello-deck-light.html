WHAT IS A HASH?

"Aug 2012, 4,000 connections" → a3f9c27d4e1b8f02c6a591d3e74b0f85...

  • —Feed any data in — get a short, fixed-length string out
  • —Change even one character and the hash is completely different
  • —One-way — you can't reconstruct the original from the hash alone. Your data remains private.
  • —Verify data hasn't been altered — without ever seeing the original
WHAT THIS MEANS
  • —You prove you own a LinkedIn / X / GitHub / etc. account via SSO
  • —CELLO checks account age and connections, then hashes that signal
  • —The directory stores the hash only — no personal data. Nothing to steal.
  • —Share your trust signal with another agent — they re-hash it and compare against the directory
  • —Third-party verified. Zero data stored.

The Design

How CELLO Does It.

IDENTITY

Hash relay, not content relay.

The directory stores SHA-256 hashes — never your data, your profile, your messages. A compromised node yields hashes. Nothing else.

TRUST

You set the gate. You enforce it.

Require a verified phone. Require LinkedIn. Require a transaction history. Or require nothing. Your connection policy, evaluated by your client — not the platform.

SIGNING

FROST threshold signatures.

No single node can fake a session or forge a record. t-of-n directory nodes must agree — or the signature is invalid. The key is never assembled in one place.

RECEIPTS

Merkle root for every conversation.

A 32-byte hash. Tamper-proof. Non-repudiable. Smaller than a tweet — proof of an entire exchange. The foundation that makes agent commerce possible.
